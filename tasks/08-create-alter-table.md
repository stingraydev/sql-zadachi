## 98. Нормализация: разнести каталог книг в authors + books (PK/FK)

*средняя* · Диалекты: PostgreSQL

В книжном отделе «Котомаркета» каталог хранится одной плоской таблицей: в каждой строке — название книги и **полное имя автора текстом**. У плодовитых авторов имя дублируется в десятках строк, при опечатке оно «разъезжается», а отдельной сущности «автор» просто нет. Это нарушает **третью нормальную форму (3НФ)**.

Нужно спроектировать схему-замену из **двух связанных таблиц**, чтобы автор хранился ровно один раз, а каждая книга ссылалась на него по ключу.

Создай (только `CREATE TABLE`, **никаких** `DROP` / `IF EXISTS` / `CASCADE`):

1. **`authors`** — справочник авторов:
   - `author_id` — целочисленный **первичный ключ** (PRIMARY KEY);
   - `name` — имя автора, текст, обязательное (NOT NULL).

2. **`books`** — каталог книг:
   - `book_id` — целочисленный **первичный ключ**;
   - `title` — название книги, текст, обязательное (NOT NULL);
   - `author_id` — целое, обязательное, **внешний ключ** (FOREIGN KEY), ссылающийся на `authors(author_id)`.

Таблицу `authors` создавай **раньше** таблицы `books` — иначе ссылка во внешнем ключе будет указывать на ещё не существующую таблицу.

Ничего вставлять и выбирать не нужно — проверяется только структура схемы (наличие PK на обеих таблицах и FK из `books` в `authors`).

**Таблицы:**

- **authors**: `author_id` integer 🔑 — Первичный ключ автора — уникальный идентификатор, на который ссылаются книги.; `name` varchar(100) — Имя автора. Обязательное (NOT NULL). Хранится ровно один раз — устраняет дублирование текстового имени из плоского каталога.
- **books**: `book_id` integer 🔑 — Первичный ключ книги — уникальный идентификатор записи каталога.; `title` varchar(200) — Название книги. Обязательное (NOT NULL).; `author_id` integer — Внешний ключ на authors(author_id). Обязательный (NOT NULL): каждая книга привязана к одному автору из справочника.

## 99. Котомаркет: разнести заказ в 3НФ

*средняя* · Диалекты: PostgreSQL

История покупок хранится в одной таблице, поэтому сведения о покупателях и заказах повторяются для каждой позиции. Разделите данные на три связанные таблицы.

Создайте таблицу `customers`:

- `customer_id` — целое число, первичный ключ;
- `full_name` — обязательное текстовое поле;
- `city` — текстовое поле, которое может быть пустым.

Создайте таблицу `orders`:

- `order_id` — целое число, первичный ключ;
- `customer_id` — обязательное целое число со ссылкой на покупателя из таблицы `customers`;
- `ordered_at` — обязательная дата заказа.

Создайте таблицу `order_items`:

- `item_id` — целое число, первичный ключ;
- `order_id` — обязательное целое число со ссылкой на заказ из таблицы `orders`;
- `product_name` — обязательное текстовое поле;
- `qty` — обязательное целое число больше нуля.

Свяжите таблицы первичными и внешними ключами так, чтобы заказ нельзя было привязать к несуществующему покупателю, а позицию — к несуществующему заказу.

Используйте только команды `CREATE TABLE`. Не используйте `DROP`, `IF EXISTS` и `INSERT`.

**Таблицы:**

- **customers**: `customer_id` int 🔑 — Первичный ключ покупателя — каждый клиент хранится здесь ровно один раз.; `full_name` text — Имя покупателя, обязательно (NOT NULL).; `city` text — Город покупателя, может отсутствовать (NULL допустим).
- **orders**: `order_id` int 🔑 — Первичный ключ заказа — каждый заказ хранится один раз.; `customer_id` int — Внешний ключ на customers(customer_id): к какому покупателю относится заказ. NOT NULL.; `ordered_at` date — Дата оформления заказа, обязательна (NOT NULL).
- **order_items**: `item_id` int 🔑 — Первичный ключ позиции заказа.; `order_id` int — Внешний ключ на orders(order_id): к какому заказу относится позиция. NOT NULL.; `product_name` text — Название купленного товара, обязательно (NOT NULL).; `qty` int — Количество единиц товара в позиции, обязательно и больше нуля (CHECK qty > 0).
